# 数据存储与远程推理

**QMD 索引位于本机，不代表笔记内容不会发往远程。** 使用远程 embedding 时，服务端会收到可读的笔记文本块。

## 数据放在哪里

| 数据 | 位置与用途 |
|---|---|
| Obsidian 原始笔记 | 当前 vault。Aha 不把 vault 作为一个目录上传到推理服务器。 |
| QMD 全文、标题、路径、向量与查询缓存 | 本机 QMD SQLite 索引。默认路径为 `~/.cache/qmd/<index>.sqlite`，环境配置可以改变它。 |
| Aha 设置、搜索轮次与反馈 | 当前 vault 的插件 `data.json`。直接填写的 API key 也在这里。 |
| 模型权重与推理进程 | 配置为本地推理时在本机，配置为远程端点时在该服务器。 |
| 请求日志、临时推理缓存 | 由接收请求的服务决定。索引在本机不能证明服务端不记录文本。 |

## 哪些文字会发送

| 操作 | 使用远程服务时发送的内容 |
|---|---|
| `qmd update` | 扫描索引配置中的 collection，更新本机全文与元数据。它不替代后续向量生成。 |
| `qmd embed` | 将需要嵌入的笔记分块，携带相应标题发送给 embedding 服务，再把返回的向量写入本机索引。 |
| 快速插入双链 | 将选中文字或段落发送给 QMD embedding 服务召回笔记。配置 QMD 远程重排端点时，还会把查询和候选正文句子／片段发送给该服务选择原文摘录。此路径不执行查询扩展或 DeepSeek 关系判断。 |
| QMD 查询扩展 | 将检索文字放入提示词，发送给配置的生成服务。 |
| QMD rerank | 将查询文字和候选原文片段发送给配置的重排服务。 |
| Aha 完整关系判断 | 将源笔记与候选的摘录发送给配置的 DeepSeek 服务。 |

具体调用取决于实际检索路径和设置，不是每次操作都调用所有模型。更新索引时，新的或发生变化的内容需要重新嵌入。全新索引的首次嵌入可以覆盖整个索引范围。

## 远程服务器能否看到原文

能。Embedding 和重排服务必须接收可读文本才能完成当前请求。服务器管理员可以访问处理中的文本，也可以配置日志或其他记录。

SSH 隧道或 HTTPS 保护传输过程。它们不阻止目的服务器读取请求正文。本机端点若通过 SSH 转发到远程，同样属于远程推理。

Aha 不控制第三方服务的保存策略。没有观察到正文日志，不能证明历史请求从未保存，也不能保证未来不保存。

## 控制范围

- 如果不希望原文离开机器，将相关 QMD 模型配置为本地推理。使用完整 Aha 关系判断时，还需单独考虑 DeepSeek 的数据路径。
- Aha 的 `Excluded folders` 只过滤召回候选。需要控制索引内容时，调整 QMD collection 的目录或匹配规则。
- 开启自动索引意味着后续达到阈值时可以自动执行 update 和 embed。若 embedding 为远程服务，新增或变化的文本块会按该配置发送。
- 不要提交插件 `data.json`、私人索引、带原文的 traces 或服务密钥。

QMD 配置与手动验收见 [安装与验收](qmd-setup.md)。运行记录应说明使用本地还是远程模型，以及验证过哪些实际请求。
